Reference Architecture · as implemented

AI Email Suggested-Response System

Repo-accurate map of the Hiver Open Challenge submission: RAG replies grounded in an uploaded company-data bundle, scored with two unblended numbers — RAGAS response quality (Tier 1) and human-feedback reliability (Tier 2) — then routed AUTO / REVIEW / ESCALATE / IGNORE. Nothing company-specific lives in src/. Sample fixtures: tests/fixtures/northpeak/ (not shipped under data/).

Transport / control LLM call Persist (StructuredStore / BlobStore) Hard AUTO gate External connector
Path A · live

Inbox → Review

Fetch → parse → event bus → classify → generate → RAGAS → route → queue → human feedback. Entry: React UI Inbox / Review (FastAPI /api/*).

Path B · batch

pipeline.py --all

Holdout tickets → generate → RAGAS evaluate → reliability report from feedback_events. No classifier / router / queue.

Path C · assist

Assistant page

Paste email → generate_reply only; optional on-demand RAGAS. No routing or queue write.

The live pipeline, step by step

Twelve stages — every module that runs on Sync Inbox

01

ingest · external

Fetch unread mail

src/email_source.py · fetch_unread() — one connector interface. demo is offline (empty inbox by default; dry-run sends); mcp is an MCP client to a Gmail (or any) MCP server. Tools are auto-mapped by capability; Settings holds the server URL + token.

demo | mcpIncomingEmail[]
02

normalize

Parse & verify

src/email_parser.py · parse() — strips HTML, truncates quoted-reply / signature blocks, collapses whitespace, folds smart punctuation. Surfaces auth_status (pass / fail / unavailable) from a provider Authentication-Results header when present — never fabricates a pass. Classification and generation always see one shape.

html_strippedquote_strippedauth_status
03

isolation · StructuredStore

Event bus persist

src/event_bus.py — publish() enqueues each parsed email (idempotent on email_id); drain(process_fn) runs each inside its own try/except. Failure retries up to 3× then moves to dead_letter. One bad email never blocks the rest of a sync. Manual paste on the Inbox page skips the bus and calls the router directly.

table: event_busretry ×3dead-letter
04

triage · LLM

Classify LLM

src/classifier.py · classify() — LLM triage via purpose="classify" (CLASSIFY_LLM_*). Categories: refund · cancellation · complain · billing · technical_support · general_inquiry · other. other ⇒ IGNORE (no generate/eval). If an order ID is present and the model returns other, remapped to general_inquiry. Frustration stays a cheap regex for queue priority only.

7 categoriesother → IGNOREfrustration regex
05

order + intent

Order lookup & intent scope

detect_order_id() finds the first known order in the body (else a placeholder transaction). Intent maps the classifier category onto policy categories (src/intent.py / generator mapping) so retrieval is scoped — plus always-on global escalation rules. Region / as-of date come from the loaded policy when available.

active transactionscategory scopeglobal rules
06

retrieval · hybrid

Policy + ticket context

src/policy_ingest.py + src/policy_store.py — format-aware ingest (PDF / DOCX / Markdown / txt), structured rules (id · condition · outcome · category · effective date), cached by section content-hash via BlobStore (policy_index/*). Retrieve = BM25 + local sentence-transformers embeddings, fused with Reciprocal Rank Fusion (optional cross-encoder rerank, off by default).

src/retriever.py — TF-IDF over past tickets. Batch fits only on split=="corpus". Live UI also includes Settings-managed user_examples (production-only — never the batch eval harness). Past tickets teach voice/tone only; they must never override policy.

BM25 + embeddings + RRFTF-IDF ticketsBlobStore cache
07

reasoning · LLM

Generate reply + structured remedy LLM

src/generator.py · generate_reply() — one RAG-prompted call through llm_client.complete(purpose="generate"). Hierarchy in the prompt: policy determines the remedy; transaction confirms conditions; past tickets teach voice. Emits reply, cited_rules, and a structured remedy ({remedy_type, remedy_amount, rule_cited, escalate} used later for deterministic edit classification — not for LLM-judged scoring.

cited_rulesremedy.escalateanthropic · openai · mistral · mock
08

Tier 1 · automated

RAGAS response quality LLM judges

src/ragas_evaluator.py + src/evaluator.py — pin ragas==0.4.3. Scores Faithfulness, Answer Relevancy, and ContextPrecisionWithoutReference via ragas.metrics.collections.*.ascore(**kwargs). Persist each score in the ragas_scores table. Routing-only combo (never shown as a blended “accuracy” headline):

quality_score = 0.5·faithfulness + 0.3·answer_relevancy + 0.2·context_precision

Also runs a sampled dual-pass retrieval disagreement check (top-k cited rule vs full-document rule extraction). When sampling skips the check, disagreement_checked=false and retrieval_disagreement=null — never treated as agreement. Deterministic length / placeholder / absolute-claim checks remain as non-blended diagnostic flags + confidence penalty.

faithfulnessanswer relevancycontext precisiondisagreement sample
09

control system

Router decision hard gates

src/router.py · route_email() — confidence = clamp(quality_score × 100 − deterministic_penalty, 0, 100).

NEVER AUTO if: faithfulness < FAITHFULNESS_GATE (default 0.7)
OR retrieval_disagreement == true
OR scoring_error
OR any deterministic flag

ESCALATE if remedy.escalate or confidence < T2 (default 50). AUTO if confidence ≥ T1 (default 80) and all gates pass. Else REVIEW. IGNORE when classifier said other. A fraction of AUTO items are hash-sampled for audit (audit_sample_rate, default 5%). AUTO never auto-sends — it only queues a pre-approved draft.

AUTO · REVIEW · ESCALATE · IGNOREt1 / t2audit sample
10

queue · StructuredStore

Persist to review queue persist

src/queue_store.py · upsert() — priority-sorted queue (escalate > review > auto, plus order value + frustration). Dedupes on email_id; never clobbers human statuses (sent / simulated / dismissed on re-route. Optional notify.send_digest() after sync when digest is enabled.

table: queuepriority sortnotify digest
11

Tier 2 · human

Review actions → feedback persist

api.py (Review page) + src/feedback.py — Send / edit / dismiss / flag hallucination / confirm escalation audit. On Send, classify_send_label() diffs the structured remedy: unchanged → ACCEPTED_AS_IS; remedy field change → EDITED_MAJOR; wording-only → EDITED_MINOR. Labels also include REJECTED, ESCALATED_CORRECTLY, ESCALATED_MISSED, FLAGGED_HALLUCINATION. Append-only rows in feedback_events. Send goes through send_reply(dry_run=not live_send).

table: feedback_eventsremedy diffdry-run default
12

Tier 2 · reliability

Reliability & Evaluation UI

src/reliability.py / src/validate_metric.py / Evaluation page — two unblended panels. Critical error rate uses only human-labeled AUTO as denominator; audit coverage is reported separately. Every rate carries n + Wilson 95% CI; n < 20 → insufficient data. Calibration buckets RAGAS quality_score deciles against real acceptance.

critical_error_rate =
count(EDITED_MAJOR | REJECTED | ESCALATED_MISSED | FLAGGED_HALLUCINATION
  ∧ routing_decision == AUTO ∧ labeled)
/ count(routing_decision == AUTO ∧ labeled)

Cross-cutting

Storage, gates, and design rules

Storage

Pluggable StructuredStore + BlobStore

Default local SQLite + filesystem (src/storage/). Opt-in Postgres / S3 / Azure / GCS from Settings. Company source files are uploaded via Settings and versioned under company/ in BlobStore; operational data (queue, feedback, scores, index cache) goes through the adapters. Nothing outside src/storage/ imports sqlite3 / boto3 / Azure / GCS SDKs.

Fail closed

Scoring errors never AUTO

RAGAS / scoring failures set scoring_error and gate AUTO → REVIEW. Disagreement unchecked ≠ agreement. No hand-labeled answer key; no synthetic control replies.

Data leakage

Holdout never retrievable

TicketRetriever fits only on split=="corpus". user_examples are live-UI only. No pre-written correct-answer file for any ticket.

Company-agnostic

Everything company-specific is uploaded

Activate a policy document, transactions export, and optional ticket history through Settings — zero code changes. Sample fixtures live under tests/fixtures/northpeak/; demo files are not shipped under data/. No hardcoded rule IDs, product names, or remedies in src/, prompts, or the router.
